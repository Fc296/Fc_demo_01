## my_02 Godot 工程骨架搭建

在 `E:\AAAproject\素材\my_02` 里按用户给的分层方案，从零搭出 Godot 4.7 工程骨架（此前该目录只有 `Sprites/`，**没有 project.godot**，所以 Godot 打不开）。

### 关键教训（重要）
- 第一轮对话在"创建文件"之前就因模型服务错误中断，用户以为已经写好了，问"写在哪、为什么 Godot 启动不了"。
  → **结论：任何涉及创建文件的任务，必须在本轮内真正落盘并给出可验证证据（路径 + 编辑器/引擎校验输出），不能只描述计划。**
- Godot 能否"打开"一个目录，唯一判断标准是有没有 `project.godot`。用户目录里只有素材 → 必须补 `project.godot`。

### 已创建结构
```
project.godot          含 [autoload] EventBus/GameData、[input] 映射、物理层命名、gl_compatibility
框架说明.md            分层地图 + 依赖方向表 + 三条约定 + 完整掉落流程 + 上手顺序
Autoload/              event_bus.gd（广播） / game_data.gd（全局值）
data/                  item_base.gd, weapon_data.gd, potion_data.gd, equipment_data.gd,
                       skill_data.gd, loot_table.gd
Scripts/               actor.gd, fsm.gd(StateMachine), state.gd(State),
                       inventory_data.gd, player_stats.gd
Scenes/character/player/player.gd      Scenes/character/enemy/enemy.gd
Scenes/drop_item/      drop_item.gd, loot_spawner.gd
ui/slot/slot.gd        ui/{inventory,equipment,skill,stats,chest}/panel.gd
```

### 约定（沿用用户给的架构）
- 每个 `.gd` 只写 `extends` / `class_name` + 中文文档注释（职责、边界、易错点），
  底部统一是「接口清单」（注释掉的变量/函数签名）——**代码待用户逐个打开注释实现**。
- 数据层用 `Resource`（可在编辑器建 .tres，不写代码造物品）。
- `Actor` 不认识"玩家"；`Player`/`Enemy` 只加各自独有逻辑。
- UI 是容器的"投影"，只读 + 重画，不存数据。
